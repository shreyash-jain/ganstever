# ARCHITECTURE — Gans-te-Ver

How the site is built, the exact commands, the image pipeline, and the traps. Verified
against the repo on 2026-08-21.

---

## Stack

Next.js **16.2.6** (App Router, Turbopack) · React 19 · TypeScript · Tailwind ·
**static export** — `next.config.ts` sets `output: "export"`, so every route prerenders
to HTML in `out/` and is served as plain files. `images.unoptimized` is on, because
`cldImage()` already returns a fully optimised Cloudinary URL (`f_auto,q_auto,c_limit`)
and a static export has no image-optimisation server.

Media lives on **Cloudinary** (cloud `dprx4pret`, folder `ganstever/`), not in the repo.

```
edit .tsx / src/lib data
        │
        ▼
  npm run build  ──►  out/  (static HTML + JSON-LD baked in)
        │
        ▼
  Cloudflare Pages (build cmd `npm run build`, output dir `out`)  ──►  live
                                   ▲
        Cloudinary ── photos at request time
```

## Commands

| What | Command |
|---|---|
| Install | `npm install` |
| Dev server | `npm run dev` |
| **The build that matters** | `npm run build` |
| Type check | `npm run typecheck` |
| Lint | `npm run lint` |
| Local Cloudflare preview | `npm run preview` (build + `wrangler pages dev --port 8790`) |

> On Windows `npm run build` sometimes **exits 1 with no error text** while still
> producing a complete `out/` — a Turbopack worker-teardown quirk. Linux builders exit 0.
> Judge the build by whether `out/` is complete, not only by the exit code.

## Deploy

Cloudflare Pages, production branch `main` (auto-rebuilds on push). Live at
**https://ganstever.com** / `https://ganstever.pages.dev`.

**The dashboard build command must be `npm run build` with output dir `out`.** It lives
only in the Cloudflare dashboard (Settings → Builds & deployments) — it cannot be set from
a repo file, and only the boss holds Cloudflare access. If it is ever set to
`npx @cloudflare/next-on-pages@1`, the build fails at install with an `ERESOLVE` peer
conflict (newer `wrangler` wants `@cloudflare/workers-types@^5`, next-on-pages wants
`^4`) — and it is the wrong tool for a static site regardless. A failed deploy on
2026-07-13 traced to exactly this.

A CI guard (`.github/workflows/build.yml`) runs `npm ci && npm run build` on push/PR to
`main` to catch breakage before Cloudflare does.

`@cloudflare/next-on-pages` and `wrangler login` (OAuth) both fail on this Windows
machine; the static export avoids the former, and a `CLOUDFLARE_API_TOKEN` is the route if
a terminal deploy is ever needed.

## Generating blog images (OpenRouter)

Blog images are generated by the session itself — the marketing lead never saves,
downloads or renames a file. Art direction and per-post prompts are written fresh for
each post (see `BLOG_PLAYBOOK.md` and `CLIENT.md`); there is deliberately **no shared
prompt library**, because the right look depends on the subject.

**The key lives outside every repo**, at:

```
C:\Users\Admin\.blog-keys.env
```

`C:\Aadi` is itself a git repository, so nothing secret may live under it. Never copy the
key into a repo, never print it, never paste it into chat. The file holds
`OPENROUTER_API_KEY` and `OPENROUTER_IMAGE_MODEL`.

Write a **throwaway** script into the session scratchpad — never into this repo — holding
this post's prompts. The API contract:

```js
// scratchpad/gen-images.mjs  —  run with: node scratchpad/gen-images.mjs
import { readFileSync, writeFileSync } from "node:fs";

const env = Object.fromEntries(
  readFileSync("C:/Users/Admin/.blog-keys.env", "utf8")
    .split(/\r?\n/)
    .filter((l) => l.trim() && !l.trimStart().startsWith("#") && l.includes("="))
    .map((l) => [l.slice(0, l.indexOf("=")).trim(), l.slice(l.indexOf("=") + 1).trim()])
);

const jobs = [
  { file: "public/images/<public_id>.png", prompt: "…40–70 words… No people, no text, no logos. 16:10." },
  // one entry per image slot
];

for (const { file, prompt } of jobs) {
  const res = await fetch("https://openrouter.ai/api/v1/chat/completions", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${env.OPENROUTER_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      model: env.OPENROUTER_IMAGE_MODEL,
      messages: [{ role: "user", content: prompt }],
      modalities: ["image", "text"],
    }),
  });
  const json = await res.json();
  if (!res.ok) throw new Error(JSON.stringify(json).slice(0, 800));
  const url = json.choices?.[0]?.message?.images?.[0]?.image_url?.url;
  if (!url) throw new Error("no image in response: " + JSON.stringify(json).slice(0, 800));
  writeFileSync(file, Buffer.from(url.split(",")[1], "base64"));
  console.log("wrote", file);
}
```

> **If the API response shape differs from the above, fix this file.** It is the repo's
> memory of the contract — correcting it once saves every future session the
> rediscovery. Note what worked and the date.

**Verified working 2026-08-21.** The recipe above ran unchanged against
`google/gemini-3-pro-image` (~25 s per image) and `google/gemini-3.1-flash-image`
(~18 s), both returning `choices[0].message.images[0].image_url.url` as a
`data:image/png;base64,...` URL. Output was 16:9 and honoured the "no people, no
text, no logos" constraints. **`qwen/qwen-image-3` does not exist on OpenRouter** —
there are no Qwen image models there, and it fails with `404 No endpoints found that
support the requested output modalities`. If a model id is ever rejected, list the
valid ones with `GET https://openrouter.ai/api/v1/models` and filter on
`architecture.output_modalities` containing `image`.

Then `python scripts/upload-to-cloudinary.py` pushes them to the `ganstever/` folder, and
you add the key to `src/lib/images.ts`. The filename *is* the Cloudinary public_id.

**Verify every generated image before showing it to anyone:** open it and actually look at
it, confirm no two slots are byte-identical (`md5sum public/images/*`), confirm the aspect
ratio, and confirm the provenance comment in `images.ts` still tells the truth about which
images are AI and which are Madelaine's.

## Traps (each of these has bitten us)

**Never force-push `main`.** A GitHub Action ("force-push reverter", commit `f697565`)
watches `main` and reverts force pushes. `origin/main` also advances without warning when
the boss merges a PR. Always `git fetch` and **rebase** onto `origin/main` before pushing.
`src/lib/images.ts` conflicts often, because each post adds an AI-illustrative section
before the Open Graph block — **keep both sections.**

**Bad merges duplicate `export const dynamic = "force-static"`.** Both
`src/app/sitemap.ts` and `src/app/robots.ts` carry that line (required under
`output: "export"`). A sloppy PR merge duplicated it in `sitemap.ts`, failing the Turbopack
build with *"the name `dynamic` is defined multiple times"* — which silently blocked every
Cloudflare deploy off `main`. **Check both files after any merge.**

**A broken `main` fails quietly.** Cloudflare keeps the last good build, so the site looks
fine while your change never ships. `npm run build` before every push.

**`postcss.config.mjs` malware.** A recurring obfuscated build-time payload across these
repos, hidden behind hundreds of spaces so it renders as a blank line. **Clean here = 8
lines / 103 bytes / longest line 31 chars.** Detect by line length, never by eye:

```bash
awk '{print length}' postcss.config.mjs | sort -n | tail -1     # expect ≤ 40
```

Branch poisoning has also been seen: every non-`main` branch force-pushed onto a fake
merge commit carrying the payload. **If anything on the remote looks tampered with, stop
and escalate — do not attempt a cleanup from a blog session.** The remediation playbook is
`.saral/docs/PLAYBOOK-force-push-worm-future-sessions.md` in the krazy-kreators repo, and
it is a technical-owner job.

**`.github/workflows/*` can't be pushed from this machine** — the git credential lacks the
`workflow` scope. Workflow changes have to go through someone whose token has it.

**Stale `.next` after deleting a route** — delete `.next` and rebuild if the build
complains about a module it cannot find under `src/app/…/blog/…`.
